# 原理讲解（写给新手）

> 这份文档尽量不用术语，用比喻讲清楚 NineLens 是怎么工作的。

---

## 一、它为什么能“看见”球的位置

游戏是 **Godot 引擎**做的。Godot 有个特点：启动时会读根目录下的 `override.cfg`，这个文件里可以声明「开机自动运行的脚本」。

我们就是靠这个进去的：

```
override.cfg  →  告诉游戏：去加载 nbr_cheat.gd
nbr_cheat.gd  →  我们的脚本
```

结果：脚本和游戏本体跑在**同一个进程**里。

打个比方 —— 别人做外挂是在体育馆外面隔着窗户看比赛，我们是直接坐在裁判席上，手里还有比赛的账本。

进去以后，游戏里所有对象都是可读的：

| 游戏内部的东西 | 我们能读到 |
|---|---|
| `Global.cue_ball` | 白球坐标（精确到小数点后两位） |
| `Global.ball_spawn_root` 下的 ball1~ball16 | 每颗球的坐标、编号、是否还在桌上 |
| `Table/PocketArea` 下 6 个袋口 | 每个袋的位置和半径 |
| `Global.shoot(力度)` | 游戏自己的**出杆函数**，可以直接调用 |

所以“看见球”不是靠图像识别，而是**直接问游戏要数据**。

## 二、瞄准线是怎么算出来的

### 第 1 步：白球该停在哪 —— 幽灵球

要把目标球打向某个袋，白球不能撞球心，得撞在**球心后面一点**：

```
幽灵球位置 = 目标球位置 − (朝袋口的方向) × 两个球半径
```

想象有一根看不见的手指把球往袋口方向推，白球必须先站到目标球**背面**的某个位置，推的时候才能对准袋口。这个位置就是「幽灵球」，屏幕上那个青色小圈。

### 第 2 步：白球真的会撞上吗 —— 射线求交

白球沿瞄准方向前进，什么时候会碰到目标球？

数学上等于「一条直线和一个圆什么时候相交」。程序算出**白球走多远会擦到目标球**，这个距离记作 `t`，然后就知道撞点在哪：

```
撞点 = 白球位置 + 瞄准方向 × t
```

> 这里踩过坑：早期用「两球心距离 − 两倍半径」当撞点，那公式**只在正对球心时成立**。大角度薄球时会短一截，屏幕上的线就断在球前面。后来老老实实解射线方程才对。

### 第 3 步：目标球往哪飞 —— 连心线

撞上之后，目标球沿**两个球心的连线**飞出去。

很多人以为“球顺着白球方向走”，其实不是 —— 是顺着连心线走。白球擦得越偏，目标球飞得越斜，这就是大角度球“甩出去”的原因。

所以屏幕上的绿线，是从目标球沿着连心线延长的方向。

## 三、怎么判断“这球能不能进”

三个条件同时成立才算能进：

```
① 目标球出球线到袋口中心的垂直距离 < 袋口半径（留 15% 余量）
② 白球到撞点这一路没被别的球挡住
③ 目标球到袋口这一路也没被挡住
```

“挡没挡”的计算方法是：求**球心到线段的最短距离**，小于两个球半径（0.5）就算挡。

HUD 里的「容差 ±1.3°」是这么来的：把瞄准方向左右各偏 0.5°、1°、1.5°…… 再算一遍，还能进的最大偏移量就是容差。容差越小，说明越需要打准。

## 四、线条怎么画到 3D 画面上 —— 投影

游戏是 3D 的，我们的线是 2D 的，靠**投影**连起来：

```
3D 世界坐标 (x, y, z)
      ↓  相机投影
屏幕上的像素坐标
      ↓  在叠加层上画线
你看到的那条线
```

具体做法：新建一个透明的 2D 画布盖在游戏画面上，每帧把算好的 3D 点转成屏幕点，再连线。

所以这些线**不修改任何游戏模型**，只在你的屏幕上绘制。这也解释了为什么联机时对面看不到线。

## 五、`F8` 为什么“杆头歪着也能进”

这是整个项目最取巧的一步，分为两层：

### 第一层：借游戏自己的出杆函数

```
Global.shoot(力度)
```

这是游戏自带的函数，调用它就等于走了一遍正常出杆流程。力度与速度的关系是实测出来的：

```
初速度 = 2 × 力度      （力度 5 → 白球以 10 飞出）
```

### 第二层：出杆瞬间纠正方向

游戏的瞄准角由它自己维护，我们写进去的值可能被改掉。所以出杆后的一瞬间，读白球的**实际速度**：

```
如果 实际方向 与我们算的方向 相差 > 10°
    就把速度方向改成我们算的方向，速度大小不变
```

直接改物理量，不依赖杆子有没有对准。所以杆头歪着、画面和你瞄的方向不一致，球还是按算好的线路走。

> 还有保底：如果 `shoot()` 没生效，依次退到「再调一次」→「模拟左键」→「直接给白球加速度」。

## 六、力度怎么定

按距离估：

```
力度 ≈ 2.7 × √(总距离) + 1.2        夹在 2 ~ 14 之间
```

开根号是为了让力度增长变缓：距离翻 4 倍，力度只翻 2 倍，避免远球一杆打飞。

## 七、为什么它不改游戏文件

只在游戏目录里多放两个文件：

```
nbr_cheat.gd    脚本
override.cfg    让游戏加载它
```

游戏本体（那个几百 MB 的 exe）、存档、dll 一个都没碰。所以卸载就是删掉这两个文件，删完和原版完全一致，连 Steam 的「验证文件完整性」都不需要。

## 八、踩过的坑（都是同一个病：假设代替实测）

| 问题 | 错误假设 | 实际情况 |
|---|---|---|
| 线不跟鼠标 | 以为瞄准角存在 `CueRotater.rotation.y` | 那个值**恒为 0**，真值在杆身朝向 |
| 边库球没线 | 以为库边在固定坐标 5.16 | 得用物理射线**实测**内壁位置 |
| 大角度线歪 | 以为撞点 = 球心距 − 2R | 得解**射线与圆交点** |
| 自瞄抽搐 | 以为一次推到位就行 | 镜头有缓动，得按步长配阻尼 |

记住一句话：**能实测的东西，别靠假设。**

## 九、想自己学，按这个顺序

1. **Godot 基础**：节点、场景树、信号（官方文档中文版够用）
2. **GDScript 语法**：和 Python 很像，两三小时能读
3. **向量**：只要懂“方向 = 两点相减再除以长度”
4. **射线与圆相交**：搜索 “ray circle intersection”，公式四行
5. **投影**：搜索 “world to screen”，Godot 里就一个函数

练手项目：用 Godot 做个小球台，实现“点鼠标，画出白球到鼠标方向的线”。练熟之后，除了“找游戏内部对象”那步，其余你都能自己写。
